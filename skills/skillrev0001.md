# スキル改良・コピー

## 呼び出し

- 「このスキルを進化させて」「このスキルを改良して」: 同じスキルIDを保ったまま更新する。
- 「このスキルを元に別のスキルを作って」「コピーして」: 元を変更せず、新しいスキルIDで派生作品を作る。

## 共通の準備

1. IDまたは固定URLが指定されていない場合は、公開中の共通目次 `/skills/index.md` を読み、名前や説明が一致する候補を調べる。複数候補がある、または対象を一意に特定できない場合は、候補ごとのタイトル・説明・ID・固定Markdown URLを示して利用者に選んでもらう。選択されるまで更新・コピー用リンクを作らない。
2. 選択された対象の実際の固定Markdown URLを読み、可能なら読み取り専用の `GET /api/skills/{id}` も確認する。表示名や古い会話だけからID、本文、revisionを推測しない。
3. 現在のタイトル・説明・本文と、利用者が望む変更を確認する。改良なら変更後の内容と差分を見せてから引き渡す。
4. 既存スキルの改良では本文の言語と内容を維持する。新規作成の英語既定ルールを理由に既存本文全体を英語へ翻訳しない。翻訳は利用者が明示的に求めた場合だけ行う。
5. 組み込みの不変スキルは上書きしない。別スキルとして使う場合はコピーして新しいIDを発行する。

## 同じスキルIDを更新する

1. 対象が利用者作成の更新可能なスキルであることを確認する。実際のMarkdownとAPIレコードを読めない場合は自動更新リンクを作らず、手動編集画面を案内するか、最新の本文を利用者に求める。
2. 新しい一意な32桁の小文字16進 `handoffId` と、6〜8桁の `receiptCode` を生成する。`receiptCode` は先頭の0を保つためJSON文字列にする。
3. 確認済みの更新案を次のJSONペイロードにする。`expectedRevision` はAPI応答にrevisionがある場合に数値で含める。revisionが得られない場合はそれを省略し、実際に読んだタイトル・説明・Markdownを一字一句変えず `sourceSnapshot` に含める。

   ```json
   {
     "type": "skill-update",
     "id": "existing-skill-id",
     "title": "更新後タイトル",
     "description": "更新後の説明",
     "markdown": "更新後のMarkdown本文",
     "receiptCode": "012345",
     "handoffId": "0123456789abcdef0123456789abcdef",
     "expectedRevision": 7
   }
   ```

   revisionがない場合の代替フィールドは次のとおり。架空のrevisionやスナップショットを作らず、実データを取得できなければ手動編集に切り替える。

   ```json
   "sourceSnapshot": {
     "title": "取得した現在のタイトル",
     "description": "取得した現在の説明",
     "markdown": "取得した現在のMarkdown本文"
   }
   ```

4. UTF-8のJSONをシリアライズし、パディングなしのBase64URLにして、既存の `/skills/{id}/edit#factory=` の `#factory=` の後に置く。origin・path・fragmentを含む完成URL全体を計測し、65,553文字以下であることを確認する。超過・不正・開けないリンクは、内容を切り詰めずコピー＆ペーストと手動編集画面に切り替える。
5. 利用者には、このリンクを開くとブラウザーが同じIDへ一度だけ更新要求を行うと伝える。AI Studioはrevisionがあれば `If-Match` で確認し、なければ現在のデータと `sourceSnapshot` が完全一致することを確認してから更新する。競合・不一致なら上書きせず失敗として扱う。ChatGPTがAPIへ直接書き込むとは説明しない。
6. 成功画面のコピー用ボタンで検証用プロンプトをコピーし、元のChatGPT会話へ貼り付けてもらう。生成時の `receiptCode` と完全一致するか照合する。プロンプトに含まれるサーバー応答の実際のMarkdown URLとrevisionを用いて、可能なら固定Markdown URLを取得し、`GET /api/skills/{id}` のrevision・同一ID・本文を確認する。応答にないURLやrevisionを推測しない。
7. receiptCodeが一致し、かつ読み取り可能な場合に実測した内容だけを報告する。receiptCodeが不一致なら結果を確認できないと伝える。登録後のURLやAPIレコードへアクセスできない場合は、ブラウザーが更新成功を返したことと、Markdown内容・revisionを独立確認できなかったことを分けて報告する。読めないことを更新失敗と断定しない。
8. ブラウザーが更新失敗または競合を返した場合は、成功扱いにしない。元データと更新案を保ち、最新状態を読み直して再検討するか、手動編集を案内する。リンクが開けない場合も更新済みとは言わず、コピー＆ペースト／手動編集に切り替える。

## 別のスキルとしてコピーする

1. 元の固定Markdownから派生版を作り、元スキルは更新しない。
2. 新規登録フローを使って、新しいタイトル・説明・本文を `https://studio.kanazawa-u.work/skills/new` へ渡す。新規本文は、利用者が別言語を指定しない限り英語で作成する。
3. 新しいIDと固定URLがブラウザーの登録成功応答で返るまで、登録済みと説明しない。
4. 登録後は新しい固定URLを共通目次へ追加する案を用意する。利用先ボットの目次が必要なら、その更新案も別途作る。

## 共通ルール

- スキルの本体Markdownとスキル目次は別のリソースとして扱う。
- ChatGPTからのリンク起動はブラウザーでの登録・更新を行う仕組みであり、ChatGPTのAPI書き込みではない。
- コピー用検証プロンプトが戻ったらreceiptCodeを照合し、サーバーが返した実URL・revisionを使って確認する。実際に取得できなかったものは未検証と報告する。
- 成功、失敗、リンクを開けない状態を混同しない。実測していない保存・更新・URLを作り話で補わない。

## 実装上の受け渡し
有効なAI生成スキル登録リンクを開くと、利用者のブラウザーがAI StudioのAPIへ1回だけ登録を送信し、保存成功を実際の応答で確認します。通常の `/skills/new` は従来の手動登録フォームです。ChatGPTからAPIへ直接書き込むことはありません。リンクが長すぎる、壊れている、または開けない場合は、Markdownをコピーして手動フォームへ貼り付けてください。

## 既存スキルの更新
更新時は対象の固定Markdown URLと `GET /api/skills/{id}` の実データを取得し、実際の `revision` と本文に基づいて `/skills/{id}/edit#factory=...` のリンクを作ります。リンクを開いたブラウザーが最新revisionを再取得し、`If-Match` を付けた `PUT /api/skills/{id}` を一度だけ行います。revisionが取れないときは、読んだ元データと現在の保存内容が完全一致する場合だけ更新します。競合・不一致なら上書きせず、手動編集へ切り替えます。更新後もIDと固定Markdown URLは維持されます。ChatGPTがAPIへ直接書き込むことはありません。
